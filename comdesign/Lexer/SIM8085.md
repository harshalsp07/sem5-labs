## 2. Complete Memory Address Map

The lexer uses well-defined memory regions across the 64 KB address space:

| Memory Address Range | Size | Component / Purpose | Description |
| :--- | :--- | :--- | :--- |
| **`2000H – 27FFH`** | 2 KB | **Input MiniC Source Buffer** | Source code stored as ASCII bytes (null-terminated with `00H` or `$`). |
| **`2800H – 2FFFH`** | 2 KB | **Output Token Array** | Sequentially stored **2-byte token records** `(Token_Type, Token_Value)`. |
| **`4000H – 43FFH`** | 1 KB | **Lexer Executable Code** | Assembled machine code of `lexer.asm` (Program Entry Point: `4000H`). |
| **`7F00H – 7F10H`** | 17 B | **Status & State Registers** | Pointers, counters, and temporary token attributes (see below). |
| **`FFFFH` (down)** | — | **System Stack** | Top of RAM, initialized via `LXI SP, 0FFFFH`. |

---

### **Detailed State Variables in Memory (`7F00H – 7F10H`)**

| Address | Size | Variable Name | Purpose / Meaning | Expected After Reference Test |
| :--- | :--- | :--- | :--- | :--- |
| **`7F00H - 7F01H`** | 2 Bytes | `SRC_PTR` | 16-bit address of the current read position in `2000H+`. | `3CH 20H` (Points to `203CH`) |
| **`7F02H - 7F03H`** | 2 Bytes | `TOK_PTR` | 16-bit address of the current write position in `2800H+`.| `3AH 28H` (Points to `283AH`) |
| **`7F04H`** | 1 Byte | `TOK_CNT` | Total number of valid tokens extracted. | `1CH` (28 decimal tokens) |
| **`7F05H`** | 1 Byte | `LINE_NUM` | Current line counter in source code (starts at 1). | `07H` (Line 7) |
| **`7F06H`** | 1 Byte | `CUR_TYPE` | Type ID of the most recently scanned token (`00H-09H`). | `00H` (`TOK_EOF`) |
| **`7F07H`** | 1 Byte | `CUR_VAL` | Value attribute byte of the most recently scanned token. | `00H` |
| **`7F08H - 7F10H`** | 9 Bytes | `CUR_NAME` | Buffer storing current identifier string (max 8 chars + `\0`). | `\0` |

## 3. Token Encoding Structure in Memory (`2800H+`)

Every token recognized by the scanner is written to memory at `2800H` as a **2-byte record**:

```
Token Address = 2800H + (2 * k)
```

- **Byte 0 (Address `2800H + 2*k`):** `Token_Type` (Numeric Type ID from `00H` to `09H`)
- **Byte 1 (Address `2800H + 2*k + 1`):** `Token_Value` (Attribute: 8-bit unsigned integer for numbers, ASCII code for identifiers, `00H` for operators/keywords)

### **Token Code Reference Table**

| Token ID | Symbolic Name | Value Byte Semantics | Example Lexeme | Memory Stored Bytes |
| :---: | :--- | :--- | :--- | :---: |
| **`00H`** | `TOK_EOF` | `00H` (End of input sentinel) | `\0` or `$` | `00 00` |
| **`01H`** | `TOK_INT` | `00H` (Keyword `int`) | `int` | `01 00` |
| **`02H`** | `TOK_IDENT` | ASCII character code of variable name | `'a'` (`61H`), `'b'` (`62H`) | `02 61`, `02 62` |
| **`03H`** | `TOK_NUM` | 8-bit unsigned integer value (0 to 255) | `5` (`05H`), `120` (`78H`) | `03 05`, `03 78` |
| **`04H`** | `TOK_PLUS` | `00H` | `+` | `04 00` |
| **`05H`** | `TOK_MINUS` | `00H` | `-` | `05 00` |
| **`06H`** | `TOK_STAR` | `00H` | `*` | `06 00` |
| **`07H`** | `TOK_SLASH` | `00H` | `/` | `07 00` |
| **`08H`** | `TOK_EQUAL` | `00H` | `=` | `08 00` |
| **`09H`** | `TOK_SEMI` | `00H` | `;` | `09 00` |

## 4. Step-by-Step Walkthrough on Sim8085 Website

Follow these steps to demonstrate the lexer on [sim8085.com](https://sim8085.com):

### **Step 1: Paste Code into the Editor**
1. Open [sim8085.com](https://sim8085.com) in your web browser.
2. Select and delete any default sample code in the left editor panel.
3. Open [`lexer.asm`](file:///home/harshal/course/comdesign/Lexer/lexer.asm), copy the entire code, and paste it into the Sim8085 editor.

### **Step 2: Assemble the Program**
1. Click the green **"Assemble"** (or **"Load"**) button in the top toolbar.
2. The assembly status will indicate success, and the Program Counter (`PC`) will be set to `4000H`.

---

### **Step 3: Enter the MiniC Source Code at `2000H` in Memory View**
1. In the **Memory View** panel (bottom or right side of the screen), find the address search box.
2. Type **`2000`** (or `2000H`) and press **Enter** to jump to address `2000H`.
3. Enter the ASCII hex bytes for your MiniC test program.

#### **Reference Program (Test Case 1):**
```c
int a;
int b = 5;
int c = a * b + 3;
int d;
d = c - b * 2;
```

#### **Hex Bytes to Enter at `2000H`:**
```
Address : Hex Bytes to Type
--------:----------------------------------------------------------
2000    : 69 6E 74 20 61 3B 0A 69 6E 74 20 62 20 3D 20 35
2010    : 3B 0A 69 6E 74 20 63 20 3D 20 61 20 2A 20 62 20
2020    : 2B 20 33 3B 0A 69 6E 74 20 64 3B 0A 64 20 3D 20
2030    : 63 20 2D 20 62 20 2A 20 32 3B 0A 00
```

*(Note: The `00` at `203BH` is the null terminator).*

---

### **Step 4: Execute the Lexer**
1. Ensure `PC` is at **`4000H`**.
2. Click the **"Run"** button to execute the entire lexer program at full speed.
3. The simulator will scan all characters, classify tokens, write them to memory, and stop when it hits `HLT` at address `402FH`.

## 6. How to Demonstrate in a Lab Viva / Evaluation

When presenting this project to an evaluator or instructor, showcase these 5 steps:

1. **Explain the Architecture:** Point out the memory map (Source at `2000H`, Tokens at `2800H`, Program at `4000H`, Status at `7F00H`).
2. **Show the 2-Byte Record Structure:** Explain why each token occupies 2 bytes `(Token_Type, Token_Value)` and how numbers store binary integers (e.g., `120` -> `78H`) while identifiers store ASCII codes (e.g., `'a'` -> `61H`).
3. **Demonstrate Number Accumulation (`MULT10`):** Explain how the shift-and-add arithmetic ($8B + 2B + d$) enables multi-digit decimal number extraction on an 8-bit CPU without a hardware multiplier.
4. **Step-Through Execution:** Use the **"Step"** button on the website to step through `WS_LOOP` and `IDENT_LOOP`, watching the `HL` and `DE` register pairs update.
5. **Verify Memory:** Jump to `2800H` in the memory table to show the token array, and to `7F04H` to show the final token count.
